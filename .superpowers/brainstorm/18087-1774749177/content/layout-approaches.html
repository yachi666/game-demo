Battle Map Rework Directions

目标一致：参考《天天富翁》的产品结构，但做原创城市乐园风格。区别在于资源依赖、完成度和迭代速度。

A. 程序化 UI 优先

A. 程序化 UI 优先

几乎不依赖外部贴图，靠面板、渐变、几何卡槽做质感。速度最快，但离商业地图感还有一层。

B. 混合式成品化

B. 混合式成品化

用 Stitch 生成底图、中心舞台和牌槽纹理，再用 Cocos 负责动态文案、状态和交互。产品感最稳，后续也最好维护。

C. 重贴图拟真复刻

C. 重贴图拟真复刻

大量依赖生成或手工贴图，努力逼近商业手游截图观感。短期最像参考图，但资源迭代和适配成本最高。

我推荐 B 的原因

  • 比 A 更像真正产品界面，不再是黑底文字原型。
  • 比 C 更容易维护，状态变化继续交给 Cocos 代码。
  • 适合现在这个阶段：先拉到“能看”的成品感，再逐步替换资源。

B 的代价

  • 需要补一批原创背景、中心舞台和地块底板资源。
  • 场景层级和渲染节点要重构，不是小修小补。
  • 要额外验证 Stitch 资源在 Cocos 中的适配效果。
